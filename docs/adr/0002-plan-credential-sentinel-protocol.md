# 0002 — 计划凭据哨兵协议（档案解析 + 确认时注入）

日期：2026-10-05  状态：已接受

## 背景

AI 生成迁移配置需要连接凭据。让 LLM 接触/生成真实密码不可接受（会进上下文、日志、
会话存储）；让用户在聊天里口述密码同样不可接受且易错。

## 决策

1. LLM 槽位密码一律填类型族哨兵（__PWD_mysql__/__PWD_pg__/__PWD_oracle__）。
2. 数据源档案作为一等事实：槽位可引用 profile 名，服务端从 vault 解密真实 DSN、
   把密码换成哨兵后进入计划产物（可存储、可展示）；档案端点不出现在
   credential_slots（UI 不向用户重复要密码）。
3. confirm 时：档案端点从 vault 重新解析回填真实 DSN（yaml.Node 精准编辑），
   手填哨兵由请求 credentials 注入；注入后重过 config.Load 再激活。
4. confirm(execute) 成功启动任务时，把完整可执行配置经 vault **加密**存为会话
   产物（kind=config），支撑"取用配置"复用；明文永不落存储。
5. 会话历史/恢复端点返回的 YAML 一律是脱敏版；apply 对含未注入哨兵的产物拒绝激活。

## 备选与理由

- 明文 DSN 存会话：审计与泄漏面不可接受。
- 每次执行都要用户重输密码：档案已持有凭据，重复索取是 UX 倒退。
- 把真实密码放进浏览器 localStorage：跨会话泄漏面大，违背"浏览器不接触"。

## 后果

+ 密码的传播路径被限制为：vault → 服务端内存 → worker 环境变量；可审计。
- 协议规则多（哨兵剔除、档案回填、加密产物），实现分散在 ai_facts/ai_confirm/
  ai_sessions——由 ai_facts_test/ai_sessions_test 锁定行为。
